## Architecture Target

The target is an ALSA-native Audio 8 DJ driver path:

- PCM playback, 8 channels.
- PCM capture, 8 channels.
- A/B/C/D stereo pair naming and routing.
- 44.1/48 kHz first.
- 88.2/96 kHz only after physical validation.
- ALSA controls for input mode, ground lift flags, software lock, profiles, and
  diagnostics.
- ALSA rawmidi in/out.
- PREEMPT_RT-friendly USB isochronous hot path.
- PipeWire/JACK/DAW compatibility.

## Packaging Target

Primary:

- Debian.
- Ubuntu.
- Debian/Ubuntu derivatives.

Secondary:

- Fedora.
- RHEL derivatives.
- RPM systems via `akmods`, DKMS, or kmod strategy.

Suggested package split:

- `opena8dj-dkms`
- `opena8dj-tools`
- `opena8dj-alsa-ucm`
- `opena8dj-udev`
- optional `opena8dj` metapackage

The first packages must not auto-load, auto-bind, reset USB, restart audio
services, or run hardware tests.

## Candidate Payload Rule

A Linux candidate is not only `.ko`.

It must include:

- driver source/module channel;
- tools;
- profile/config schema;
- udev rules if needed;
- ALSA UCM profiles if needed;
- `README-FIRST`;
- uninstall/rollback instructions;
- diagnostics/verify report tooling;
- hashes and build metadata;
- debug/symbols policy;
- provenance and licensing notes;
- readiness labels and limitations.

## Shared Hardware Lock

No hardware was used by the Linux agent.

Future hardware-affecting actions require:

```sh
export AUDIO_GATE_LOCK_ROOT="$HOME/.opena8dj/hardware-gate.lock"
```

Actions requiring the lock:

- module load/unload against live hardware;
- USB bind/unbind/reset;
- playback/capture;
- iRig or other physical capture;
- Traktor/DVS;
- CPU/audio latency measurement.

Build-only, docs, and static analysis do not require the lock.
