# OpenA8DJ Windows Standalone Installer

This directory owns the design for the Windows installer line. It is separate
from the macOS packaging path and must stay separate.

The installer is split into two independently versioned products:

1. `OpenA8DJ Windows Driver`
2. `OpenA8DJ Windows Tools`

The driver installer owns the kernel driver package and Plug and Play install.
The tools installer owns user-mode utilities, diagnostics, future control UI,
Start Menu entries, and logs. A future bundle EXE can install both, but the two
products must remain independently buildable and uninstallable.

## Product Split

### OpenA8DJ Windows Driver

Purpose:

- Install the Microsoft-signed `OpenA8DJUsb` driver package.
- Bind to `USB\VID_17CC&PID_1978`.
- Put the INF/CAT/SYS package into the Windows Driver Store.
- Install, upgrade, repair, and remove the driver package.
- Leave user-mode tools untouched unless the user explicitly chose the bundle.

Payload:

- `OpenA8DJUsb.inf`
- `OpenA8DJUsb.sys`
- `OpenA8DJUsb.cat`
- optional symbols in internal QA builds only
- driver package manifest with SHA256 hashes
- signing state and certificate/cat verification report
- uninstall/rollback instructions

Installer technology:

- Development: signed ZIP generated by `windows\scripts\package-installer.ps1`.
- Production: elevated bootstrapper EXE that calls the Windows driver install
  API or `pnputil.exe`.
- Avoid DIFx. It is deprecated and should not be the long-term driver install
  path.

The production driver installer must not install a fake or unsigned package.
For public release, the catalog must be Microsoft-signed through attestation or
HLK/WHQL submission.

### OpenA8DJ Windows Tools

Purpose:

- Install user-mode tools without touching the Driver Store.
- Provide diagnostics and future control UI.
- Work even when the driver is not installed, but report that state clearly.

Payload:

- `opena8djctl.exe`
- future `OpenA8DJ Control Center.exe`
- future diagnostic collector
- future logs directory
- future Start Menu shortcuts
- future optional PATH entry for CLI users
- profile/config import/export support when implemented

Installer technology:

- MSI is acceptable for tools because it only installs user-mode files.
- WiX Toolset is the preferred implementation path.
- The tools MSI must not run driver installation custom actions.

## Bundle Strategy

A future `OpenA8DJ-Windows-Setup.exe` can be a bootstrapper that chains:

1. `OpenA8DJ Windows Driver`
2. `OpenA8DJ Windows Tools`

The bundle is a convenience wrapper only. The driver and tools products remain
separate packages with separate uninstall entries.

Recommended UX:

- Default: install both driver and tools.
- Advanced: driver only, tools only, or repair existing install.
- Detect whether Windows test-signing is active for development packages.
- Refuse public installation if the driver catalog is not Microsoft-signed.
- Show a reboot-required state when Windows requires it.

## Hardware Lock Policy

Installer builds do not touch hardware and do not need the shared hardware lock.

Driver install, uninstall, repair, upgrade, and device rebinding can affect the
physical Audio 8 DJ device and must acquire the shared hardware lock. The
current PowerShell install/uninstall scripts already do this through
`OpenA8DJ.WindowsCommon.psm1`.

Tools install/uninstall does not need the lock unless a future installer step
talks to the device.

## Installation Flow

Driver installer:

1. Verify admin elevation.
2. Verify package layout and SHA256 hashes.
3. Verify catalog signature.
4. For development packages only, optionally import the test certificate.
5. For development packages only, optionally enable test-signing and stop for
   reboot if it was not already active.
6. Acquire the shared hardware lock.
7. Install the driver package into the Driver Store.
8. Bind or rebind matching `USB\VID_17CC&PID_1978` devices.
9. Write install manifest under `local-analysis\windows`.
10. Release the shared hardware lock.

Tools installer:

1. Verify target architecture.
2. Install tools under `%ProgramFiles%\OpenA8DJ\Tools`.
3. Install Start Menu entries.
4. Optionally install command-line PATH integration.
5. Do not acquire the hardware lock.
6. Do not modify the Driver Store.

Bundle installer:

1. Check prerequisites.
2. Run driver installer when selected.
3. Run tools installer when selected.
4. Run verification when selected.
5. Show exact result: installed, reboot required, failed, or blocked by lock.

## Verification Contract

The standalone installer is not ready until these checks pass on Windows:

- clean install on Windows 10 22H2 x64
- clean install on Windows 11 current x64
- uninstall, reinstall, and upgrade
- reboot after install
- unplug/replug Audio 8 DJ
- `opena8djctl.exe surface`
- `opena8djctl.exe topology`
- `opena8djctl.exe diagnostics`
- Driver Store contains `OpenA8DJUsb.inf`
- connected USB device is detected as `VID_17CC&PID_1978`
- install manifest contains file hashes and signature state
- lock is released after success and after failure

The current `verify-driver.ps1` report is the first machine-readable output for
this contract.

The development ZIP must also include `README-FIRST.txt` with install, reboot,
verify, uninstall, and limitation notes for testers.

No Windows candidate is complete if it contains only `OpenA8DJUsb.sys`. The
minimum candidate must include the driver package, tools, install/uninstall
entry points, verification tooling, hashes, signing state, and limitations.

## Release Channels

### Development

Output:

- `OpenA8DJUsb-Release-x64-installer.zip`

Signing:

- local test certificate
- test-signing mode required

Audience:

- developers only

### Internal QA

Output:

- driver installer EXE
- tools MSI
- optional bundle EXE

Signing:

- organization certificate where possible
- Microsoft-signed driver preferred before broad QA

Audience:

- controlled testers

### Public Release

Output:

- Microsoft-signed driver installer
- tools MSI
- optional bundle EXE

Signing:

- driver package signed through Microsoft attestation or HLK/WHQL
- installer EXE/MSI signed with the project/company code signing certificate

Audience:

- public users

## Implementation Milestones

1. Keep the current ZIP package as the development installer.
2. Add a driver installer bootstrapper project once a Windows build host is in
   place.
3. Add a tools MSI project using WiX once there is more than one user-mode tool.
4. Add a bundle EXE only after driver and tools installers are independently
   reliable.
5. Gate public release on Microsoft-signed driver package and clean install
   matrix.

## Non-Goals

- No macOS files in the Windows installer.
- No Native Instruments binaries, logos, firmware, or proprietary payloads.
- No placeholder MSI that only copies files and claims driver support.
- No silent hardware-changing actions without the shared hardware lock.
- No streaming/audio success claim until the Windows audio endpoint and real
  isochronous engine pass validation.
